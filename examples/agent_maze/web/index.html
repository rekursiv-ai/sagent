Decentralized agent teams win — centralized ones choke

Both runs start with a single agent that must spawn a team (it doesn't know how big) and coordinate to open every lock. The only difference is the team topology — watch the decentralized team grow and coordinate in parallel and finish, while the centralized team funnels everything through one agent and stalls.

The puzzle

A foggy maze of corridors. Each lock is two plates sharing a letter, placed in different corridors, out of sight of each other. Some corridors are dead-ends with no plate.

The goal

Open every lock. A lock opens only when its two plates are pressed on the same turn by two different agents — so the team must explore, find each other, and synchronize.

Decentralized vs Centralized

Both start with one first agent. Decentralized: any agent can spawn more agents and message anyone — the first agent is just a peer. Centralized: only the first agent may spawn, and every message routes through it — it's the team's lone coordinator.

What sagent makes easy

Recursive budgeted spawn + any-to-any messaging + broadcast, native and composable in one model — so the decentralized strategy is actually available and trivial to wire, not three subsystems bolted together.

Why the centralized team chokes and the decentralized one scales

Two things funnel through the centralized team's single coordinator, and both serialize. Spawning: only the coordinator can grow the team, one agent per turn, so it can't field enough hands in time. Coordination: each lock is an independent pairing; the decentralized team resolves them in parallel (O(1) rounds) while the coordinator mediates every one in turn (O(K)). That is the whole story — no single sagent primitive is exotic; sagent just makes the decentralized wiring (recursive spawn + any-to-any messaging) as easy as the centralized one, so the strategy that actually scales is available at all.
